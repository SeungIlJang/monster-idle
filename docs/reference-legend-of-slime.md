# 레전드 오브 슬라임 — 화면 분석과 적용안

참고 자료: 플레이 스크린샷 8장 + 트리플샷 만렙 영상(youtube.com/shorts/dpe_UgB1pz4).
버전 v4.16.0 기준.

이 문서는 "무엇을 베낄지"가 아니라 **왜 그렇게 만들었는지와, 우리 구조에 맞는 형태**를 적는다.
그대로 옮기면 안 되는 것도 이유와 함께 적어 둔다.

---

## 0. 한 줄 요약

우리는 **시스템을 거의 다 갖췄는데 그중 무엇도 화면에 보이지 않는다.**
레전드 슬라임이 우리보다 나은 지점은 밸런스가 아니라 **같은 수치를 보여주는 방식**이다.

가장 큰 격차 셋:

| | 레전드 슬라임 | 무럭무럭 몬스터 (현재) |
|---|---|---|
| 동료 | 화면에서 **같이 싸운다** | `S.own.comp` 라는 **숫자만** 존재. 화면에 몸이 없다 |
| 해금 | 월드맵이 **해금 일정표** 역할 | `slotUnlock: [10,40,100,200,400]` 이 코드에만 있다 |
| 획득 | 새 동료·새 콘텐츠마다 **연출** | 조용히 숫자가 올라간다 |

## 1. 전투 화면 (영상 + 스크린샷 5)

### 본 것
- 왼쪽에 **아군이 여러 기 뭉쳐** 있다. 영상에서는 큰 흰 동물, 슬라임, 뿔 달린 파란 몬스터 등 최소 3~5기.
  줄 맞춰 서지 않고 **겹치듯 뭉쳐** 있어서 "부대" 느낌이 난다.
- 오른쪽 적에게 거대한 보라색 장판 + 파란 번개가 쏟아진다. 화면의 절반이 이펙트다.
- 피해 숫자가 **한 번에 여러 개** 뜬다(248A가 3개 + 17.2A). 금화가 포물선으로 튀어 오른다.
- 하단: `AUTO ON` 토글 + 스킬 6칸. 쿨다운이면 회색, 준비되면 금색 테두리.
- 상단: 골드 / 젬(+) / **배속 버튼과 남은 시간(▶▶ 05:02)** / 메뉴.
- 스킬바 바로 위에 **퀘스트 한 줄**: `동료 소환 (35/35)` + `받기` + 보상 💎500.

### 왜 그렇게 했는가
방치형은 플레이어가 **보고만 있는** 시간이 대부분이다. 그 시간에 화면이 조용하면 게임이 멈춘 것처럼 느껴진다.
숫자가 여러 개 뜨고 금화가 튀는 건 "내가 세졌다"를 초당 여러 번 되먹임하는 장치다.
우리 전투는 **1초에 피해 숫자 1개**뿐이라 같은 DPS인데도 훨씬 심심하다.

### 우리에게 적용

**A. 동료를 화면에 세운다 — 수치는 그대로 두고.** ⭐ 최우선

이게 핵심이다. `comp` 배너는 이미 DPS 배수를 준다(`stats.js` `gC()`). 여기에 **피해를 더하지 않는다.**
이미 계산에 들어있는 그 DPS를 **몸으로 보여주기만** 한다.

- 표시 수: `activeSlots('comp')` (가챠 배너 레벨 기준, 최대 5)
- 누구: `S.monLv` 에 레벨이 있는 몬스터 중 리드(`S.mon`)를 제외하고 레벨 높은 순
- 배치: 리드 뒤쪽에 살짝 겹치게(`W*0.34` 기준 왼쪽·위로 흩어서). 줄 세우면 부대 느낌이 안 난다
- 행동: 리드의 공격 박자에 **0.05~0.15초씩 어긋나게** 같이 공격 모션. 어긋나야 "여럿"으로 보인다
- 크기: 리드보다 **작게**(0.75배). 누가 주인공인지 흐려지면 안 된다

> **밸런스에 손대지 않는다.** 시뮬 판정 5개를 다시 돌릴 필요가 없다 — 연출만 바뀐다.
> 이건 이 프로젝트 규칙("시뮬 판정 뒤 구현")을 우회하는 게 아니라, 애초에 수치가 안 바뀌는 작업이다.

**B. 타격 연출을 여러 겹으로.**

- 피해 숫자를 **타격당 2~3개로 쪼개** 조금씩 다른 위치·시차로 띄운다(합은 같다)
- 치명타는 더 크게·노랗게 (이미 있음) + **화면 살짝 흔들기**(`R.shake` 이미 있음, 지금은 거의 안 쓴다)
- 처치 시 금화가 **포물선으로 튀어 HUD 골드 쪽으로 빨려 들어가게**
- 보스 등장/처치에 전체 화면 플래시

**C. 배속 버튼.** 상단에 ×1/×2. 방치형에서 가장 자주 눌리는 버튼인데 우리는 없다.

**적용하지 않을 것: 스킬 6칸 바.**
우리는 액티브 스킬이 아직 설계되지 않았다. 빈 칸만 6개 두면 "미완성" 신호만 준다.
스킬을 먼저 설계하고, 그다음에 바를 붙인다. (DESIGN.md §14 에 남겨둔 항목)

## 2. 동료 (스크린샷 6)

### 본 것
- `새로운 콘텐츠!` 리본 → `동료` 제목 → 닭 캐릭터가 반짝이며 등장 → 설명 한 줄:
  "나의 소중한 파트너, 동료와 함께 인간들을 무찌르세요!"
- 해금 조건이 화면에 같이 떠 있다: `퀘스트 25 · 동료 소환 (0/35) · 💎500`

### 왜 그렇게 했는가
새 시스템이 열리는 순간을 **사건으로 만든다.** 조용히 탭이 하나 생기면 플레이어는 모르고 지나간다.
그리고 해금 직후 바로 **첫 목표(35회 소환)** 를 쥐여줘서 새 탭이 비어 보이지 않게 한다.

### 우리에게 적용
- 배너 슬롯이 열릴 때(스테이지 10/40/100/200/400), 2단계 레이어가 열릴 때 **전체 화면 연출 1회**
- 이미 `banner()` 가 있다(`combat.js`). 지금은 작은 글자 한 줄이라 존재감이 없다 → 큰 연출로 승격
- 연출 직후 "첫 목표"를 같이 띄운다 (일일퀘스트에 이미 틀이 있다)

## 3. 수집 (스크린샷 1·2·4)

### 본 것
**획득 팝업**: 등급 글자(A, 금색) + 이름 + 초상화에 보라 방사형 광선 + 보유 효과 아이콘 5개 + **고유 스킬 1개**(이름·설명).

**상세**: 등급 + 속성(🌲) 배지, LV1 `0/30` 경험치 바, **장비 4칸**(잠김), 장난감 1칸,
보유 효과 6개가 **각각 해금 레벨 표시**(LV10/25/50/75/100/★0), 고유 스킬은 **LV35 해금**.

**도감 그리드**: 등급별 색(A 주황 / S 청록 / SS 빨강), 미보유는 **회색 실루엣 + "미보유"**.
보유한 것만 색이 있고 `장착중` 표시.

### 왜 그렇게 했는가
- **실루엣**이 "아직 없는 것"을 계속 보여준다 — 뽑기를 돌리는 가장 강한 이유다. 목록에서 빈 칸은 아무 감정도 안 만든다
- 보유 효과를 **레벨마다 하나씩** 푸는 건 육성 동기를 잘게 쪼개는 장치다. "LV25까지만 더" 가 계속 생긴다
- 고유 스킬을 LV35 뒤에 두는 건 **한 마리를 깊게 키우는** 선택지를 만든다

### 우리에게 적용
우리 수집은 `S.monLv` 숫자 올리기 + 마일스톤(10/25/50/75/100에서 공격력 +2%)뿐이다. 구조는 거의 같은데 **보여주지 않는다.**

- 도감을 **그리드 + 실루엣**으로. 몬스터 10종 전부 자리를 만들고 미보유는 회색
- 마일스톤을 "LV10 · LV25 …" **아이콘 줄로** 표시해서 다음 해금이 눈에 보이게 (수치는 그대로)
- 각 몬스터에 **고유 스킬 이름**을 붙인다 — 지금은 10종이 이름 말고 다른 게 없다

**적용하지 않을 것: 장비 4칸 + 장난감.**
우리는 이미 `equip` 배너가 장비 역할을 한다. 몬스터마다 또 장비를 두면 축이 겹치고,
자동 장착이 최적해라 선택의 의미도 없다(DESIGN.md 가 수동 장착 UI 를 뺀 것과 같은 이유).

## 4. 마스터리 (스크린샷 3)

### 본 것
- 오각형 노드가 **선으로 이어진 트리**. 아래 노드를 찍어야 위가 열린다
- 노드마다 `0/15`, `0/20` 같은 투자 한도
- 지금 찍을 수 있는 노드는 **초록 테두리**로 강조
- 하단에 **변화 미리보기**: `공격력 0% 증가` → `공격력 4% 증가`
- `초기화 💎10` / `강화 SP 1`
- `일반` 탭 + 잠긴 탭 하나 (고급 트리)

### 왜 그렇게 했는가
미리보기가 핵심이다. "찍으면 뭐가 되는지"를 **찍기 전에** 보여줘야 고민이 생긴다.
초기화를 젬으로 파는 건 실수를 되돌리는 값을 받는 자연스러운 과금 지점이다.

### 우리에게 적용
우리 마스터리는 노드 3개(atk/hp/dps)짜리 평면이다. 트리로 바꿀 필요는 없다 —
**노드가 3개뿐인데 트리를 그리면 빈 그림이 된다.** 대신:

- **변화 미리보기**를 붙인다: `공격력 ×1.012 → ×1.024` (가장 싸고 효과 큰 개선)
- 찍을 수 있는 노드에 강조 테두리
- `초기화` 를 젬 소비로 추가 (현재 `resetMastery()` 는 이미 있다 — 비용만 붙이면 된다)

노드를 늘리는 건 3단계 레이어에서 같이 설계한다.

## 5. 광고 (스크린샷 7)

### 본 것
- "10분간 스킬 쿨타임을 **40% 감소**시키는 요정의 축복" — **지속 버프**형 광고
- 날개 달린 상자 + `40% 10min` + 취소 / 광고 보기
- 그 아래 **모든 광고 평생 스킵 (0/1) ₩39,900 + 젬 20000**

### 왜 그렇게 했는가
즉시 보상(젬 50개)은 한 번 받고 끝이지만, **10분 버프는 그 10분 동안 게임을 계속 보게 만든다.**
광고 시청률과 세션 길이를 동시에 올리는 설계다.
"광고 제거"를 젬과 묶어 파는 것도 영리하다 — 광고를 싫어하는 사람에게만 정확히 꽂힌다.

### 우리에게 적용
우리 광고 5곳은 전부 **즉시 보상**이다(무료 뽑기·던전 입장·광산 폭탄·연구 단축·오프라인 2배).
`ads.json` 구조는 그대로 두고 **지속 버프형을 하나 추가**한다:

- 예: "10분간 골드 획득 ×2" 또는 "10분간 공격속도 +50%"
- 상태는 `S.buff = { key, until }` 하나면 된다. 오프라인 복귀 시 만료 처리 주의
- **밸런스 영향이 있다** → 이건 시뮬에 먼저 넣고 판정받아야 한다. 하루 몇 번 쓸지를 가정해 DPS 기여를 계산

`모든 광고 평생 스킵` IAP 는 **출시 이후**에 본다. 지금은 과금 설계 자체가 없다.

## 6. 월드맵 (스크린샷 8)

### 본 것
- 세로 경로에 노드 1-1 / 1-3 / 1-5 / 1-8
- 각 노드에서 가지가 뻗어 **그 지점에서 열리는 콘텐츠 카드**: 내 슬라임, 퀘스트, 방치 보상, 축복(잠김)
- 현재 위치에 빨간 깃발, 완료는 초록 체크, 잠김은 자물쇠

### 왜 그렇게 했는가
**해금 일정을 미리 보여준다.** "1-8 가면 축복이 열린다"를 알면 1-8까지 갈 이유가 생긴다.
해금을 숨기면 그냥 숫자만 오르는 게임이 된다.

### 우리에게 적용 ⭐ 투자 대비 효과가 가장 큰 것

우리는 해금 조건이 **이미 전부 데이터로 있다**:
- `slotUnlock: equip [1,1,1] / skill [1,20,60,150] / comp [10,40,100,200,400]`
- `adv.reqStage: 60` (상급 스탯)
- 2단계 레이어 해금 스테이지

이걸 **읽어서 그리기만** 하면 된다. 새 시스템을 만들 필요가 없다.

- 스테이지 바(`#stageBar`)를 눌러 열리는 **해금 로드맵** 화면
- 지나온 것 체크, 현재 위치 표시, 다음 해금까지 남은 스테이지
- 이미 `nextSlotAt(banner)` 함수가 있다 — 데이터는 다 준비되어 있다

## 7. 우선순위

연출·표시 위주라 대부분 **밸런스를 건드리지 않는다**. 밸런스가 바뀌는 건 ⚠ 표시.

| 순위 | 작업 | 근거 | 밸런스 |
|---|---|---|---|
| 1 | **동료를 화면에 세우기** | 사용자가 영상에서 가장 먼저 본 것. 수치는 이미 있다 | 영향 없음 |
| 2 | **해금 로드맵** | 데이터가 이미 다 있어 그리기만 하면 된다 | 영향 없음 |
| 3 | **타격 연출 다층화** (숫자 분할·화면 흔들기·금화 흡입) | "엄청 화려함"의 실체 | 영향 없음 |
| 4 | **도감 그리드 + 실루엣** | 뽑기 동기를 만드는 가장 싼 장치 | 영향 없음 |
| 5 | **해금 연출** (배너 슬롯·레이어) | `banner()` 승격이면 된다 | 영향 없음 |
| 6 | **마스터리 변화 미리보기 + 초기화 비용** | 기존 함수에 UI 만 붙임 | 젬 소비 추가 |
| 7 | 배속 ×2 | 방치형 필수 | ⚠ 진행 속도 |
| 8 | 지속 버프형 광고 | 세션 길이 | ⚠ 시뮬 선행 필요 |
| — | 액티브 스킬바 | **스킬 설계가 먼저** | ⚠ 설계 단계 |
| — | 몬스터별 장비·장난감 | 축이 겹침 — 하지 않는다 | — |

## 8. 미술 방향에 대한 주의

레전드 슬라임은 **굵은 검은 외곽선 + 평면 채색 + 큰 단순한 눈**의 벡터풍이다.
우리 몬스터는 도감 시트에서 뽑은 **음영이 들어간 그림**이고, 용사는 **도트**다.
이미 두 가지가 섞여 있다.

슬라임을 레전드 슬라임 스타일로 새로 그리면 **셋이 섞인다.** 새 그림을 넣을 거라면
몬스터 10종을 **한 번에 같은 기준으로** 다시 뽑아야 한다. 한 마리만 바꾸면 그 한 마리만 떠 보인다.

→ 디자인 프롬프트는 `assets/mon/prompts.json` 에 10종 공통 규격으로 작성했다.
