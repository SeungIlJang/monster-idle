# 로직 담당 전달 — 무럭무럭 몬스터 효과음 적용 요청

사용자가 효과음 1차 세트를 게임에 적용하도록 요청했습니다. 아래 파일을 사용해 재생 시스템과 이벤트 연결을 구현해 주세요. 현재 이 효과음은 게임에 미적용 상태입니다.

## 프로젝트와 원본

- 프로젝트: `D:/AI/workspace/game/monster-idle`
- 효과음 폴더: `D:/AI/workspace/game/games/output/monster-idle/sfx-v1/audio`
- 설계와 재생 기준: 상위 폴더 `README.md`, `manifest.json`
- 개별 청취: 상위 폴더 `index.html`
- 전체 ZIP: `D:/AI/workspace/game/games/output/monster-idle/monster-idle-sfx-v1.zip`
- 형식: 48kHz / mono / PCM16 WAV. 게임용 10개 약 429KiB.
- 직접 합성한 원본이며 외부 녹음 샘플은 사용하지 않았습니다. 이번 전달은 적용 요청이지 장시간 청취 품질의 최종 승인을 의미하지 않습니다.

## 구현 방식

1. 작은 오디오 모듈 하나에서 로딩·재생·동시 발음·음량·음소거·정지를 관리해 주세요. 매 프레임 새 Audio 객체를 만들지 말고 버퍼를 재사용합니다. 사용자 시작 버튼 등 실제 입력 이후에 AudioContext를 활성화하고, 기기에서 정지된 컨텍스트를 복구할 수 있게 합니다.
2. 전투 모듈에서 소리 파일을 직접 불러오기보다 실제 전투 사건을 전달하고 메인 쪽에서 재생을 연결해 주세요. 현재 `src/main.js`의 `setEventHandler`는 클리어 후 UI 갱신·에셋 예열을 담당하므로 이 동작을 보존해야 합니다. `src/combat.js`의 실제 공격, 피격, `onKill` 지점과 성공한 강화·뽑기 지점을 확인하세요.
3. 공격은 최소 120ms 간격·동시에 최대 2개, 전체 동시 발음은 최대 6개를 초기값으로 둡니다. 같은 변주의 즉시 반복을 피합니다. 제한 시간은 게임 dt나 2배속 시간이 아닌 실제 시간 기준입니다.
4. 처치는 150ms 이내 사건을 묶습니다. 적 여러 마리, 동료 5기, 금화 파티클 5~9개마다 각각 소리를 내지 마세요. 스킬 처치에서 일반 처치가 중복 호출돼 두 번 재생되지 않도록 확인합니다.
5. 강화 버튼 길게 누르기는 최대 250ms마다 한 번입니다. 실패하거나 재화가 부족하면 성공음을 내지 않습니다.
6. 10회 뽑기는 시작음 한 번 + 최고 등급 결과음 한 번입니다. 일반·희귀 결과음을 동시에 내거나 10개 결과음을 겹치지 마세요. 희귀 판정은 실제 `G.RARITIES` 등급 이름/순서를 확인해 매핑합니다. 광고 완료 전이나 실패한 뽑기에는 성공음을 내지 않습니다.
7. 보상음에 높은 우선순위를 주고 재생 중 평타 음량을 잠시 낮춥니다. 현재 파일도 공격 -10dBFS, 피격 -11dBFS로 보상보다 작게 설계했으므로 전부 개별 최대 음량으로 재정규화하지 마세요.
8. 효과음 음량과 음소거를 사용자가 조절하고 다음 실행에도 유지할 수 있게 합니다. 기존 세이브 키·게임 진행 데이터·밸런스를 바꾸지 않는 방식으로 적용하세요.
9. 화면이 숨겨지거나 광고가 재생되면 소리를 중지/일시정지하고, 복귀 시 대기 중이던 소리를 몰아서 재생하지 않습니다. 음원 로드나 브라우저 재생이 실패해도 전투와 UI는 정상 진행돼야 합니다.

## 완료 확인

- 실제 시작 입력 후 재생, 음소거·음량 유지, 숨김/광고 정지, 복귀 확인.
- 2배속과 다수 처치에서 중첩 폭주가 없고, 오디오 오류가 전투를 중단하지 않는지 확인.
- 강화/뽑기의 성공·실패·10회 결과를 구분해 확인.
- 파일 경로와 에셋 빌드 포함 여부를 확인하고 실제 모바일 기기에서 크기·음량·피로도를 청취.
- 적용한 파일과 이벤트, 실행한 검증, 남은 기기 청취 항목을 사용자에게 보고해 주세요.

디자인 채팅에서는 10개 파일의 파형 형식·클리핑 없음·시작/끝 0 경계만 수치 검증했습니다. 실제 기기에서의 장시간 청취까지 검증됐다고 보고하지 마세요.
